# First-Generation Guidance

You are working on the **first generation** of this app. The monorepo you were given is a blank template — `apps/web` currently renders an empty placeholder `HomePage` at `/`. Your job is to turn that template INTO the app the user just asked for.

**If the user asked for a game, stop reading this file here.** Load `vault/wiki/skills/game/SKILL.md` and follow its build order — it routes you to the references the game needs (`loop.md`, `tick.md`, `ui.md`, `feel.md`, the matching genre file, and the 2D or 3D graphics reference). Build that one full-viewport frame: plain state, a tick, one playable loop, and feel. The first screen names the goal and the verb in large type. Do not load `design`. Do not spend the build on look before that line is true. Skip the website rules below, with two exceptions: the "Every craft move must survive server rendering" paragraph still applies — the game's start, pause, and HUD overlays are server-rendered React like any other route — and the "Ship a favicon and a social share image" paragraph applies to a game like any other build. One game is different: a persistent-world brief (real-hour builds, daily logins, an empire grown over days) follows `vault/wiki/skills/game/references/genres/persistent-world.md` instead of the canvas build order — its screens are DOM pages, but it is still a game: do not load `design`, and the same two exceptions apply. Every other game is the single full-viewport frame: a game inside a scrolling page with sections is wrong for every genre but that one.

The rules below are for **website and app briefs only.**

**Ship a WOW first impression.** The first load must feel finished, memorable, and intentional — never a wireframe with placeholder sections. The visitor's first reaction should be "this looks great," not "this works."

**Bring the page to life — but vary how, every build.** Read the brief, then pick 2–4 craft moves from the categories below that fit _this_ world. Never apply the same combo twice in a row. A quiet editorial brief earns one elegant marker underline; a playful consumer app earns a marquee, tilted cards, and a confetti reveal. Pick what serves the brief — leave the rest out.

- **Kinetic typography** — animated headlines, letter reveals, hand-drawn marker/highlight strokes under a key phrase, scribble accents, large display type with subtle weight or color shifts
- **Moving strips** — horizontal marquees (news-ticker style), scrolling logo ribbons, color-line tickers, repeating word loops, infinite carousels
- **Depth & 3D feel** — subtle tilt on hover, parallax photography, perspective transforms, floating cards with offset shadows, layered z-stacks, isometric tableaus
- **Decorative graphics** — color bars, accent strokes, halftone grain, blob shapes, gradient ribbons, hand-drawn doodles, geometric accent lines, sticker-style badges
- **Scroll & cursor interactions** — scroll-triggered reveals, magnetic buttons, cursor-aware accents, smooth section transitions, sticky split scrolls

**Build it modular from the first file.** Name the sections, then create one component file per section under `src/components/home/` (for a website-first brief: `hero.tsx`, `services.tsx`, `contact.tsx`, …; for an app-first brief the same rule with that surface's own vocabulary), composed by `src/routes/home.tsx` alongside its `meta` and `loader`. Long static content — menus, plans, FAQ entries, testimonials — goes in `src/data/<name>.ts`, not inline in the section. Shared chrome (header, footer) goes in `src/root.tsx` or `src/components/`. A landing page written as one giant route file is not an acceptable first generation, however good it looks.

**Ship a favicon and a social share image — every first generation, no exceptions.** The template's `favicon.ico` is a generic placeholder, and `seo()` emits no `og:image` until a page passes one — shipped as-is, the site shows a stock icon in every browser tab and posts as a text-only card everywhere it is shared. Before finishing: (1) generate a favicon with `get_images` — one 1:1 image briefed as a flat, bold, single-subject mark on a solid background, legible at 32px — save it via `bash` with `curl -fsSL -o apps/web/public/favicon.png "<url>"`, change the icon link in `src/root.tsx` to `{ rel: 'icon', href: '/favicon.png', type: 'image/png' }`, and delete the placeholder with `rm apps/web/public/favicon.ico`; (2) pass `image` to `seo()` in the home page's `meta` — the page's own hero image when it has one, otherwise a dedicated 16:9 `get_images` image that captures the site's world; (3) pass `jsonLd` on every page the seo-sitemap reference assigns a schema to — the home page always carries `WebSite` plus `Organization`, `Person`, or `LocalBusiness` built from the site's real copy, and blog posts, listings, products, services, events, and FAQs each get their row from that reference's table.

Keep motion **purposeful and performant** — never gratuitous. Animate `transform` and `opacity` only, respect `prefers-reduced-motion`, and isolate heavy effects to small components. For a website or app brief, follow `design/SKILL.md` for craft execution and page composition.

**Every craft move must survive server rendering.** This app is SSR: the first client render has to reproduce the server's HTML exactly, or React fails hydration and re-renders the page from scratch — the "wow" first paint becomes a flash of broken. No `Math.random()`, `Date.now()`, bare `toLocaleDateString()`/`toLocaleString()`, or `date-fns` `format()` in render; randomize inside a `useEffect` (or pick in the `loader`), format dates/numbers with an explicit locale and `timeZone`, and gate `window`-dependent effects behind `useHydrated()` from `@/hooks/use-hydrated`. See `react-router-framework-mode/references/hydration.md`.

(If this file is NOT in your context, you are on a later iteration — follow the normal rules and ignore this doc.)
